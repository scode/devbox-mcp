## 2026-10-11 10:40 — SPEC requirements: remaining top-level decisions

- No survival of in-flight turns across death of the stdio MCP process: keep it simple, no supervisor, no Unix socket,
  zero IPC. Sessions on disk stay resumable. Checked tunnel-client source (commit b91e6c9, 2026-10-09): one long-lived
  stdio child shared by all requests; it is replaced on tunnel-client restart, pipe errors, and some deadline paths
  (e.g. slow `initialize`), and must be re-initialized afterwards. Not per request, not on relay reconnect.
- Working directory: any absolute path. If the caller gives none, use a standard default of some prefix plus the session
  name. Sessions are named; names are limited to lowercase letters, digits, `_` and `-`.
- Codex interface: `codex exec --json` plus `exec resume`, not app-server. Consequence: no mid-turn steering and no live
  clarifying questions; follow-ups are new turns in the same session.
- Client: OpenAI Secure MCP Tunnel only. ChatGPT Dots (always-on ChatGPT agents announced at OpenAI DevDay 2026-09-29)
  are the motivating client; other OpenAI tunnel clients should work but are not specifically targeted.
- File split: SPEC.md is normative, agent-agnostic product behavior including the hard security requirement.
  SPEC_impl.md holds Rust, MCP SDK, storage, process model, and per-agent adapters. AGENTS.md mandates keeping code
  and both specs in sync and forbids weakening the security requirement without explicit user confirmation.
- Next: present the consolidated requirement list for agreement before writing the files.
